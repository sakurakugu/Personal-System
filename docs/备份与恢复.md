# 备份与恢复

当前仓库已经补上一套本地一键备份脚本，默认备份以下组件：

- PostgreSQL
- MinIO
- Twikoo

如果需要把 Redis 会话和缓存也一起打包，可以额外加上 `--with-redis`。

## 备份文件放到哪里

默认放在仓库根目录下的 `backups/`：

```bash
backups/
  20260421_153000/
    manifest.json
    postgres.dump
    minio-data.tar.gz
    twikoo-data.tar.gz
```

每次执行都会创建一个时间戳目录，不会覆盖旧备份。

## 创建备份

```bash
python ./tools/2.备份数据.py create
```

如果要把 Redis 一起备份：

```bash
python ./tools/2.备份数据.py create --with-redis
```

如果只想保留最近 7 份：

```bash
python ./tools/2.备份数据.py create --keep 7
```

如果要指定名字：

```bash
python ./tools/2.备份数据.py create --name before-big-refactor
```

## 查看已有备份

```bash
python ./tools/2.备份数据.py list
```

`list` 会显示每份备份的创建时间、包含组件，以及总大小（同时保留原始字节数）。

如果要看每份备份中的文件明细：

```bash
python ./tools/2.备份数据.py list --verbose
```

## 清理旧备份

如果只想保留最近 7 份备份：

```bash
python ./tools/2.备份数据.py prune --keep 7
```

这个操作会直接删除更旧的备份目录，所以执行前先确认保留数量。

## 备份前提

- 本机已安装 Docker CLI
- Docker 已启动
- 对应服务容器已在运行

脚本会直接从当前 `docker compose` 服务中导出数据：

- PostgreSQL：从 `postgres` 容器导出 `pg_dump`
- MinIO：打包 `minio` 容器内 `/data`
- Twikoo：打包 `twikoo` 容器内 `/app/data`
- Redis：先执行 `SAVE`，再打包 `redis` 容器内 `/data`

## 恢复说明

当前版本先提供稳定的备份能力，恢复流程仍建议手动执行，原因很直接：

- PostgreSQL 恢复会覆盖现有表结构和数据
- MinIO / Twikoo / Redis 恢复属于目录级覆盖
- 自动恢复一旦参数错了，破坏面会比自动备份大很多

所以现在的恢复建议是：

### PostgreSQL

先确认目标数据库就是你要覆盖的那一套，然后执行：

```bash
Get-Content .\\backups\\20260421_153000\\postgres.dump -Encoding Byte |
  docker compose exec -T postgres sh -lc 'pg_restore -U "$POSTGRES_USER" -d "$POSTGRES_DB" --clean --if-exists --no-owner --no-privileges'
```

### MinIO

先停掉 `minio`，清空目标卷，再把 `minio-data.tar.gz` 解回 `/data`。

### Twikoo

先停掉 `twikoo`，清空目标卷，再把 `twikoo-data.tar.gz` 解回 `/app/data`。

### Redis

如果要恢复 Redis，建议停服务后直接把 `redis-data.tar.gz` 解回 `/data`，再启动 Redis。

## 建议

- 大改数据库结构前先跑一份备份
- 批量删文件前先跑一份备份
- 生产环境至少保留最近 7 份
- 备份目录最好再同步到另一个磁盘或网盘
