# 文章 AI 辅助优化计划

本文记录文章编辑页 AI 辅助功能后续可以优化和扩展的方向。当前已实现基础能力：根据正文生成标题、分类、标签、摘要，以及非流式润色正文并手动应用。

## 当前功能边界

- 文章编辑页提供 `生成元信息` 和 `润色正文` 两个入口。
- 元信息建议返回标题、摘要、分类、标签和建议依据。
- 正文润色返回完整 Markdown，用户预览后手动替换正文。
- 前端对文章 AI 请求使用较长超时，避免长文润色被通用接口超时中断。
- 后端复用现有 AI 配置、权限和调用日志。

## 待办

### 近期优化

- [ ] 在 AI 抽屉中显示请求耗时、正文长度、返回长度，方便判断模型是否卡住或返回过短。
- [ ] 为 `润色正文` 增加“结果与当前正文相同”的更明显提示，并提供重新生成入口。
- [ ] 对 AI 返回内容做最小质量校验，例如正文长度异常过短时提醒用户确认。
- [ ] 在前端展示后端返回的失败原因和 axios 超时错误细节，减少“没反应”的排查成本。
- [ ] 为 AI 抽屉增加“清空结果”按钮，避免旧结果和新请求混在一起。

### 流式润色

- [ ] 新增 `POST /articles/ai/polish-content/stream` 流式接口。
- [ ] 前端使用 `fetch` + `ReadableStream` 或 SSE 接收增量内容。
- [ ] 支持实时显示生成状态、已生成字数和停止生成。
- [ ] 流式协议继续使用 `<<<SUMMARY>>>`、`<<<CONTENT>>>`、`<<<END>>>` 分隔摘要和正文。
- [ ] 长时间没有新 token 时再判定超时，而不是等待完整响应超时。
- [ ] 生成中断时保留已生成内容，并提示用户可复制或重新生成。

### Diff/Patch 应用

- [ ] 新增“生成修改建议”模式，不直接返回整篇正文。
- [ ] AI 返回结构化 patches：`old`、`new`、`reason`，前端渲染为类似 git diff 的视图。
- [ ] 应用 patch 前校验 `old` 片段仍存在于当前正文中。
- [ ] 支持逐条应用、全部应用、跳过某条建议。
- [ ] 多处相同片段时要求用户选择应用位置，避免误替换。
- [ ] patch 应用失败时 fallback 到完整润色正文预览。
- [ ] 评估是否在后端统一应用 patch，并使用片段哈希保护正文版本。

### 局部润色

- [ ] 支持润色当前选中内容。
- [ ] 支持按标题章节润色，例如只润色当前二级标题下的内容。
- [ ] 支持“只改错别字”“更口语”“更正式”“压缩篇幅”等润色模式。
- [ ] 局部润色时保留上下文提示，但只返回目标片段的修改结果。

### 元信息建议

- [ ] 分类和标签建议优先复用已有分类/标签，并在 UI 中标出“已有”和“将新建”。
- [ ] 支持生成多个标题候选。
- [ ] 支持生成多个摘要候选，例如短摘要、长摘要、SEO 摘要。
- [ ] 支持基于当前分类和标签规则生成建议依据。
- [ ] 新建分类/标签前检测大小写、空格和同义词近似重复。

### 安全与可恢复

- [ ] 所有正文替换操作都保留本地撤销快照。
- [ ] AI 应用正文前展示差异，而不是只展示完整预览。
- [ ] 应用 AI 结果后不自动保存，继续由用户手动保存文章。
- [ ] 对超长文章增加分段润色策略，避免一次请求过大。
- [ ] 对模型返回的 Markdown 做基本结构检查，例如代码块围栏是否闭合。

### 后端与日志

- [ ] 将文章 AI 请求的 token、耗时、状态写入更明确的调用来源字段。
- [ ] 失败日志中记录响应前 500 字，成功日志中记录结果长度，不记录完整正文。
- [ ] 对非流式文本调用增加可配置的单次超时时间。
- [ ] 评估是否将 AI 非流式调用和流式调用抽为统一服务层。
- [ ] 增加更多测试覆盖：协议缺失、空正文、超短返回、patch 应用失败。

### 体验细节

- [ ] AI 抽屉中增加 Tabs：`元信息`、`润色正文`、`修改建议`、`历史结果`。
- [ ] 对长润色结果增加搜索和复制按钮。
- [ ] 替换正文前显示二次确认，并说明“替换后仍需保存文章”。
- [ ] 移动端优化抽屉宽度和底部操作按钮。
- [ ] 增加“再次生成”时是否覆盖旧结果的确认或自动归档。
