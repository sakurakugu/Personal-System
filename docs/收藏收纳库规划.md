# 收藏收纳库规划

## 为什么要做

当前系统更偏向“整理后的结果管理”，但日常使用里还有大量“还没整理成结果”的素材：

- 网页收藏
- 微信里看到的内容
- 截图里的文字
- 临时复制的一段文本
- 稍后再看的资料
- 未来可能转成文章、动态、待办的素材

这些内容如果直接塞进文章、动态或文件模块，都会出现边界混乱：

- 放进文章：太重，很多内容还没到成文阶段
- 放进动态：太杂，动态更适合即时表达
- 放进文件：只能存原始附件，缺少内容结构和整理状态

所以需要单独补一个“先收进来，再整理出去”的中间层。

## 当前状态

截至 `2026-04-12`，`collections` 一期基础版已经落地，当前文档不再只是提案，而是“设计原则 + 已实现范围 + 后续待补”的合并说明。

当前已完成：

- 后端独立 `collections` 模块
- 数据表：`collections`、`collection_assets`、`collection_tags`、`collection_tag_relations`
- 管理端菜单：`收藏收纳库`
- 收藏列表页
- 新增 / 编辑收藏
- 标签、来源、类型、状态、关键词筛选
- 批量归档
- 附件上传并关联到收藏
- 一键转文章草稿
- 一键转动态草稿
- 一键转待办

当前未完成：

- 网页自动抓取标题、站点名、封面、正文
- 图片 OCR
- AI 自动摘要、自动标签、待办提取
- 浏览器插件、微信入口
- 公开展示页
- Feed 混入

所以当前模块可以正式使用，但定位仍然是：

- 先收纳
- 后整理
- 再转出

而不是“全自动采集整理系统”。

## 模块定位

收藏收纳库的职责是：

- 接收来源素材
- 保存原始内容和提取内容
- 记录整理状态
- 为后续 OCR / AI 扩展（辅助整理）预留字段
- 向文章、动态、待办输出结构化结果

一句话定义：

`收藏库是输入层，文章和动态是输出层，文件是附件层，Feed 是展示层。`

## 与现有模块的边界

### `collections` 与 `articles`

- `collections` 存未整理、半整理、待加工资料
- `articles` 存正式内容、长期内容、可发布内容

判断标准：

- 还在收集和提炼阶段，放 `collections`
- 已经形成完整表达，放 `articles`

### `collections` 与 `moments`

- `collections` 偏资料沉淀
- `moments` 偏即时表达

判断标准：

- 重点是“以后再整理”，放 `collections`
- 重点是“现在发一句”，放 `moments`

### `collections` 与 `files`

- `files` 负责保存附件本体
- `collections` 负责保存附件对应的语义信息和整理结果

例如一张截图：

- 图片文件本体存在 `files`
- OCR 文本、摘要、标签、来源、状态存在 `collections`

### `collections` 与 `feed`

- `feed` 只负责展示已发布或可见内容
- `collections` 不直接进入公开 Feed

## 命名决策

统一命名如下：

- 产品中文名：`收藏收纳库`
- 菜单名：`收藏收纳库`
- 后端模块名：`collections`
- 前端特性目录名：`collections`
- 数据表主表名：`collections`

补充说明：

- `collections` 是整个收纳模块名
- `link` 只是 `collections.type` 的一种取值
- 当前支持的内容类型为 `link`、`text`、`image`、`file`

## 已实现的一期范围

### 支持的收藏来源

当前已支持以下录入方式：

- 网页链接
- 手动粘贴文本
- 图片 / 截图
- 普通文件附件

说明：

- 链接类收藏当前是“手动录入 URL”
- 图片 / 文件类收藏当前通过现有文件上传能力接入
- 暂无自动抓取网页内容，也暂无 OCR 自动识别

### 当前已实现的处理能力

- 保存标题、链接、站点名、摘要、备注、正文提取文本、OCR 文本
- 保存来源类型、内容类型、整理状态、AI 状态
- 支持多附件关联与附件角色区分
- 支持独立标签体系
- 支持列表筛选与搜索
- 支持批量归档
- 支持手动维护整理结果

### 当前已实现的输出能力

- 一键转文章草稿
- 一键转动态草稿
- 一键转待办

### 当前明确未做

- 不做自动网页抓取
- 不做 OCR 执行链路
- 不做 AI 自动处理
- 不做浏览器插件
- 不做自动发布
- 不做公开展示页
- 不把收藏内容混入首页 Feed

## 数据结构

一期实际采用三层结构：

- 收藏主体
- 附件关联
- 标签体系

### 收藏主体 `collections`

当前字段：

- `id`
- `user_id`
- `type`
- `source_type`
- `title`
- `url`
- `site_name`
- `cover_url`
- `content_text`
- `ocr_text`
- `summary`
- `note`
- `status`
- `ai_status`
- `created_at`
- `updated_at`
- `archived_at`

字段说明：

- `type`：内容类型，当前为 `link`、`text`、`image`、`file`
- `source_type`：来源类型，当前为 `web`、`wechat`、`manual`、`screenshot`
- `content_text`：正文提取结果或用户输入正文
- `ocr_text`：OCR 原文占位字段，当前主要由人工填写或后续扩展写入
- `summary`：整理后的摘要
- `status`：资料流转状态
- `ai_status`：AI 处理状态，占位已完成，处理链路未接入

### 附件关联 `collection_assets`

当前字段：

- `id`
- `collection_id`
- `file_id`
- `asset_role`
- `sort_order`
- `created_at`

字段说明：

- `file_id` 关联现有 `files`
- `asset_role` 当前区分 `original`、`cover`、`attachment`、`screenshot`

### 标签体系

当前已采用独立标签表，而不是字符串数组：

- `collection_tags`
- `collection_tag_relations`

这样后续做标签统计、推荐、筛选会更稳定。

## 状态设计

### 收藏状态

当前实际使用：

- `inbox`：刚收进来，未整理
- `processing`：正在整理
- `ready`：整理完成，可转输出
- `archived`：已归档
- `dropped`：废弃

### AI 状态

当前实际使用：

- `pending`
- `running`
- `done`
- `failed`

说明：

- 目前 AI 状态只作为数据结构的一部分
- 后续接 AI 任务队列时直接复用，不需要再改字段

## 当前转出策略

### 转文章草稿

收藏会被整理成文章草稿，主要规则：

- 标题优先使用收藏标题
- 摘要优先使用 `summary`，其次 `note`
- 正文按“原始链接 / 站点 / 摘要 / 备注 / 正文 / OCR”拼接成 Markdown 草稿

### 转动态草稿

收藏会写入当前用户唯一的动态草稿，主要规则：# TODO: 这个会覆盖之前的草稿嘛，要先弹出提示嘛

- 标题优先使用收藏标题或站点名
- 正文优先使用摘要，其次备注、正文、OCR
- 若有 URL，会附到内容末尾

### 转待办

收藏会生成普通待办，主要规则：

- 标题使用收藏标题或链接兜底
- 描述拼接摘要、备注、链接和部分正文
- 自动补一个 `收藏` 标签

## 推荐处理流程

### 当前可行流程

#### 网页收藏

1. 手动填写 URL
2. 手动补标题、站点名、摘要、备注
3. 需要的话转文章 / 动态 / 待办
4. 整理完成后归档

#### 截图收藏

1. 上传截图到收藏附件
2. 手动补 OCR 文本或摘要
3. 需要的话转文章 / 动态 / 待办
4. 整理完成后归档

#### 文本收藏

1. 粘贴正文
2. 手动补标题、摘要、标签
3. 转文章草稿、动态草稿或待办

## 后续扩展建议

后续建议按下面顺序继续推进，而不是一次性全部铺开。

### 第二阶段

- 网页标题 / 站点名 / 封面自动抓取
- 基础正文提取
- OCR 服务接入

### 第三阶段

- AI 摘要
- 标签建议
- 待办提取
- 文章提纲建议

### 第四阶段

- 分享扩展或浏览器插件
- 移动端快捷采集
- 更细的批量整理能力

## 最终结论

本项目已经按下面方案进入可用状态：

1. 新增独立的 `collections` 模块，产品名称定为“收藏收纳库”
2. 收藏模块作为输入层，不与文章、动态、文件、Feed 混用职责
3. 一期基础版已完成录入、整理、筛选、附件、标签和转出能力
4. OCR、AI、网页自动抓取暂未接入，但字段和状态已预留

所以当前的判断不是“是否要做”，而是：

`模块已可用，后续按采集自动化和 AI 整理能力继续迭代。`
