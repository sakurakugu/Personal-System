# 前端踩坑记录

## 1. 深色模式下 ElCard 卡片透明度无法调节

### 现象
博客首页的卡片组件（`AnnouncementList.vue`、`AnnouncementFeed.vue`、`ArticleReader.vue`、`CategoryBar.vue`）在日间模式下可以通过"卡片透明度"滑块正常调节透明度，但在**深色模式下调节无效**，始终保持固定不透明背景。

### 根因

在 `src/styles/app.css` 中存在一条全局深色模式兜底规则：

```css
.dark .el-card {
  background-color: var(--bg-card) !important;
  border-color: var(--border-color) !important;
  color: var(--text-primary) !important;
}
```

该规则用 `!important` **强制固定**了所有 `ElCard` 在深色模式下的背景色。

而博客首页的其他卡片（文章卡片、统计卡片、日历卡片等）根元素都是普通的 `<div>`，不依赖 `ElCard` 组件，因此不受该规则影响；偏偏公告组件直接使用了 `<ElCard>`，导致动态透明度样式被这条全局规则彻底压死。

### 解决方案

在公告组件自身的 scoped CSS 中，给背景色声明也加上 `!important`，以覆盖全局的 `!important`：

```css
/* AnnouncementList.vue / AnnouncementFeed.vue */
.announcement-card {
  background-color: rgba(255, 255, 255, var(--overlay-card-opacity)) !important;
}

.dark .announcement-card {
  background-color: rgba(15, 23, 42, var(--overlay-card-opacity)) !important;
}
```

> 技巧：`var(--overlay-card-opacity)` 在 overlay 壁纸模式下由 `BlogHome.vue` 注入；非 overlay 模式下该变量未定义，整条 `background-color` 声明会失效，组件会自动回退到默认的 `var(--card-bg-transparent)`，无需额外判断。

### 预防建议

1. **慎用全局 `!important`**：对 `.dark .el-card` 这类大范围的组件全局覆写，使用 `!important` 会扼杀子组件的特殊化需求。如果必须兜底，尽量选择更精确的选择器，或仅在特定页面/布局中生效。
2. **检查透明度调节覆盖范围**：以后若新增直接使用 `<ElCard>` 且需要参与"卡片透明度"调节的组件，必须确保其 scoped CSS 能覆盖 `app.css` 中的 `.dark .el-card` 规则。
3. **区分容器类型**：博客首页的卡片体系分为两种——
   - **纯 `<div>` 容器**（如 `ArticleFeedCard`、`SiteStatsWidget`）：不受 Element Plus 全局样式干扰，透明度调节天然生效；
   - **`<ElCard>` 容器**（如公告列表）：会被 Element Plus 及其全局覆写影响，需额外关注 `!important` 优先级问题。
