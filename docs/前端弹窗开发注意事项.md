# 前端弹窗约定

## 结论

项目内业务弹窗统一使用 `frontend/src/components/BaseDialog.vue`，不要直接使用 `Element Plus` 的 `ElDialog`。

## 背景

控制台布局在 [frontend/src/app/layouts/DashboardLayout.vue](../frontend/src/app/layouts/DashboardLayout.vue) 中主动接管了页面滚动：

- `body` 被设置为 `overflow: hidden`
- 实际滚动发生在页面内部容器

而 `ElDialog` 默认会在打开时执行滚动锁：

- 给 `body` 添加滚动锁样式
- 根据浏览器滚动条宽度给右侧增加补偿

这两套机制叠加后，会出现以下问题：

- 打开弹窗时右侧突然出现滚动条或滚动条占位
- 页面内容整体向左挤
- 某些页面为了“防抖动”再加全局滚动槽后，右侧会长期留白

## 处理方案

基础弹窗组件 `BaseDialog` 内部固定了以下策略：

- 透传 `ElDialog` 的常用属性和事件
- 强制 `lock-scroll=false`
- 统一通过组件自身的 `v-model` 管理显隐

这样可以保证：

- 弹窗不再修改 `body` 的滚动状态
- 滚动职责只由页面布局负责
- 业务页面不需要重复记忆同一套修复参数

## 使用方式

```vue
<script setup lang="ts">
import BaseDialog from '../components/BaseDialog.vue'
</script>

<template>
  <BaseDialog
    v-model="visible"
    title="示例弹窗"
    width="480px"
    :close-on-click-modal="false"
  >
    <div>内容</div>

    <template #footer>
      <button @click="visible = false">关闭</button>
    </template>
  </BaseDialog>
</template>
```

## 约定

- 新增业务弹窗时，优先使用 `BaseDialog`
- 除非确实需要 `ElDialog` 的默认滚动锁，否则不要直接使用 `ElDialog`
- 如果后续页面重新调整为 `body` 负责滚动，也优先修改 `BaseDialog`，不要逐页散改

## 排查步骤

如果后续再次出现“打开弹窗时右侧留白”问题，按下面顺序排查：

1. 页面是否手动控制了 `body` 的 `overflow`
2. 当前弹窗是否绕过了 `BaseDialog`
3. 是否额外设置了 `scrollbar-gutter`、`padding-right` 或全局滚动条补偿样式
4. 是否有第三方组件在弹窗打开时修改了 `body` class 或内联样式
