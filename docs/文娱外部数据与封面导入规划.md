# 文娱外部数据与封面导入规划

## 背景

文娱模块后续需要支持从外部数据源获取作品信息，包括：

- 搜索外部作品
- 使用外部封面
- 将外部封面转换成 AVIF 后保存到本地对象存储
- 导入作品标题、原名、简介、创作者、分类、标签等元数据
- 保留外部来源，方便后续刷新、追踪和排查

当前 `media_items` 表还没有正式数据，旧的封面结构可以直接重构，不需要做向前兼容。

## 推荐方向

后端提供统一的文娱外部导入层，前端只调用站内 API。

整体流程：

```text
用户搜索关键词
  -> 后端调用一个或多个外部数据源
  -> 统一返回候选结果
  -> 用户选择候选作品
  -> 后端拉取详情和封面
  -> 可选本地化封面
  -> 写入 media_items、media_external_sources、media_assets
```

不建议前端直接调用外部 API。原因是：

- API key 和 OAuth 凭据应放在后端
- 外部 API 有限流和错误处理，需要统一日志和缓存
- 外部返回结构不稳定，需要后端适配成内部结构
- 封面下载、校验、AVIF 转换、对象存储上传都应放在后端

## 数据模型建议

### 作品主表

`media_items` 只保存系统内真正需要筛选、展示、编辑的字段。

建议保留或新增：

```text
id
user_id
title
original_title
media_type
status
rating
creator
summary
description
genres
tags
release_date
primary_cover_asset_id
is_visible
created_at
updated_at
```

建议移除或替换：

```text
cover_file_id
```

原因是文娱封面不是用户文件管理器里的普通文件，它更像文娱条目的业务资源。继续绑定 `files.id` 会让来源、版权、外链、本地缓存和多封面管理都变得别扭。

### 外部来源表

新增 `media_external_sources`，用于记录一个作品从哪里导入。

建议字段：

```text
id
media_item_id
provider
external_id
external_url
raw_data JSONB
fetched_at
created_at
updated_at
```

说明：

- `provider`：例如 `tmdb`、`bangumi`、`anilist`、`igdb`、`google_books`
- `external_id`：外部系统里的作品 ID
- `external_url`：外部页面地址
- `raw_data`：保留原始响应，后续补字段时不用频繁迁移
- 同一个作品可以绑定多个外部来源

建议加唯一约束：

```text
media_item_id + provider + external_id
```

也可以额外加：

```text
provider + external_id
```

是否全局唯一要看是否允许不同用户分别导入同一个外部作品。个人系统里可以先不做全局唯一，只做用户维度去重。

### 文娱资源表

新增 `media_assets`，用于管理封面、横幅、截图等资源。

建议字段：

```text
id
user_id
media_item_id
asset_type
storage_key
external_url
thumbnail_url
source_provider
source_asset_id
original_name
mime_type
width
height
size
attribution
license
is_primary
sort_order
imported_at
created_at
updated_at
```

`asset_type` 建议先支持：

```text
cover
backdrop
screenshot
logo
other
```

封面访问逻辑：

- 如果 `storage_key` 有值，使用站内 `/files/...` 生成签名 URL 或公开缩略图 URL
- 如果 `storage_key` 为空但 `external_url` 有值，使用外部 URL
- 公开页面优先展示本地托管资源，外部 URL 只作为兜底

## 封面存储策略

支持两种模式。

### 外部引用

只保存外部 URL，不下载到本地。

适合：

- 搜索候选结果
- 导入前预览
- 临时展示

缺点：

- 外链可能失效
- 可能有防盗链
- 访问速度和稳定性不可控
- 外部站点改图后本地展示也会变化

### 本地托管

后端下载外部图片，校验内容后转换成 AVIF，并上传到 MinIO。

适合：

- 用户确认使用的主封面
- 公开页面长期展示
- 需要缩略图、签名 URL 和稳定缓存的场景

推荐默认策略：

```text
搜索阶段使用外部引用，保存作品时将选中的封面本地化。
```

现有后端已经有 `准备上传载荷(..., compress_static_images=True)`，可以复用 AVIF 转换逻辑。

需要补充：

- 外部图片下载大小限制
- 下载超时
- MIME sniffing
- 图片尺寸读取
- 错误日志
- 重复资源去重

## 外部数据源建议

### 影视

TMDB：

- 适合电影、电视剧
- 数据完整，图片质量高
- 图片 URL 需要根据官方配置拼接
- 需要 API token

TheTVDB：

- 适合剧集
- 数据较完整
- API 使用门槛比 TMDB 高

### 动画、漫画、二次元

Bangumi：

- 适合动画、漫画、游戏、音乐、书籍等泛二次元条目
- 中文和日文数据较友好
- 很适合作为个人文娱库的优先数据源

AniList：

- 适合动画和漫画
- GraphQL API
- 英文生态好，字段结构比较清晰

Kitsu：

- 适合动画和漫画
- 可作为备用来源

MangaDex：

- 适合漫画
- 对漫画封面和章节数据支持较好

### 游戏

IGDB：

- 适合游戏元数据
- 需要 Twitch OAuth
- 封面、平台、公司、分类数据比较完整

RAWG：

- 适合游戏搜索和封面
- 需要 API key
- 需注意署名和使用条款

VNDB：

- 适合视觉小说
- API v2 支持作品查询和图片字段

### 书籍

Google Books：

- 适合通用书籍搜索
- 可获取标题、作者、简介、封面等
- 需要注意封面质量不稳定

Open Library：

- 适合通过 ISBN、OLID 等获取书籍封面
- 可以作为 Google Books 的补充封面源

### 音乐

MusicBrainz + Cover Art Archive：

- 适合音乐专辑、发行版本、封面
- 数据结构偏严谨
- 需要处理 release 和 release-group 的差异

### 通用图片搜索

可选：

- Brave Search API
- Google Custom Search JSON API
- SerpApi

注意：

- 通用图片搜索适合兜底，不适合作为首选元数据源
- 必须保存来源 URL
- 需要考虑版权和公开展示风险
- Bing Search APIs 已退役，不建议新接入

## 后端库建议

Python 后端建议优先使用：

```text
httpx
tenacity
aiolimiter
Pillow
pillow_avif
```

用途：

- `httpx`：调用外部 API 和下载封面
- `tenacity`：外部请求重试
- `aiolimiter`：按 provider 限流
- `Pillow`、`pillow_avif`：继续复用当前 AVIF 转换链路

后续如果图片处理性能成为问题，再考虑：

```text
pyvips
```

缓存建议使用 Redis：

- 缓存搜索结果
- 缓存详情结果
- 缓存外部图片 HEAD 或失败状态
- 减少重复请求外部 API

## 后端模块建议

建议新增：

```text
apps/cloud/backend/app/integrations/media_sources/
  __init__.py
  base.py
  bangumi.py
  tmdb.py
  anilist.py
  igdb.py
  google_books.py
  open_library.py
  rawg.py

```

统一接口：

```python
class 外部文娱数据源:
    async def search(self, keyword: str, media_type: str | None) -> list[外部作品候选]:
        ...

    async def get_detail(self, external_id: str) -> 外部作品详情:
        ...
```

统一输出 Schema：

```text
provider
external_id
title
original_title
media_type
creators
summary
description
genres
tags
release_date
cover_url
thumbnail_url
external_url
raw
```

文娱模块中再提供站内 API：

```text
GET  /media/external/search
GET  /media/external/{provider}/{external_id}
POST /media/import
POST /media/{media_id}/assets/import-cover
```

## 日志要求

外部导入链路需要添加日志，便于排查：

- 搜索使用的 provider、关键词、耗时、结果数量
- 详情拉取的 provider、external_id、耗时
- 封面下载 URL、大小、MIME、耗时
- AVIF 转换前后大小
- 对象存储 storage_key
- 外部 API 失败原因和状态码
- 限流、超时、重试次数

日志中不要输出 API key、OAuth token、签名 URL。
