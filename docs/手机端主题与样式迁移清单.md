# 手机端主题与样式迁移清单

## 当前结论

- [x] `packages` 目前可以视为“跨端通用层”
- [x] 现有通用层主要是 `packages/api` 和 `packages/domain`
- [x] 云端的 `src/modules` 是业务模块目录，不是 `CSS Modules`
- [x] 手机端当前不需要为了迁移去改成 `CSS Modules`
- [x] 手机端后续应优先对齐“目录边界”和“主题机制”，不是先对齐所有视觉细节

## 关于 `packages` 的判断

当前 `packages` 已经承担共享职责：

- `packages/api`
  - 负责接口运行时、客户端、错误处理、上下文
- `packages/domain`
  - 负责 `auth`、`todos`、`system` 等领域类型、接口封装、状态逻辑

这说明现在的方向是对的：

- [x] 业务逻辑可以优先沉到 `packages`
- [x] 纯接口层和纯领域层适合跨端复用
- [ ] 页面布局
- [ ] 手机端导航
- [ ] 云端博客视觉
- [ ] 大量页面样式

上面这些还不算稳定通用层，不要急着往 `packages` 放。

## 关于主题色和日夜模式是否同步

结论：

- [x] 需要同步“主题机制”
- [ ] 不需要现在就同步“整套云端视觉效果”

这里要区分两层。

### 应该同步的部分

这些建议尽早和云端保持同一套规则，否则以后迁组件会反复改样式变量和状态逻辑：

- [x] 统一主题状态模型：`浅色 / 深色 / 跟随系统`
- [x] 统一主题主色模型：`hue`
- [x] 统一本地存储键名：`theme`、`hue`
- [x] 统一根节点切换方式：给 `document.documentElement` 加或移除 `dark`
- [x] 统一基础 CSS Token 命名
  - [x] `--hue`
  - [x] `--selection-hue`
  - [x] `--el-color-primary`
  - [x] `--el-color-primary-light-*`
  - [x] `--el-color-primary-dark-*`
  - [x] `--bg-primary`
  - [x] `--bg-card`
  - [x] `--text-primary`
  - [x] `--border-color`

如果后面手机端要迁入云端组件，只要这些机制一致，样式迁移成本会明显降低。

### 不需要现在同步的部分

这些现在不建议直接搬：

- [ ] 云端博客壁纸、横幅、樱花等外观系统
- [ ] 云端所有 `.dark .el-*` 的大面积覆盖样式
- [ ] 云端桌面端专用布局视觉
- [ ] 为博客和控制台服务的复杂视觉变量

原因：

- 手机端现在的产品形态和云端不同
- 云端大量主题样式是围绕博客页和桌面控制台展开的
- 现在整套搬过去，只会让手机端样式变重，后面还得再删

## 推荐实施方式

### 第一阶段：先在手机端对齐主题机制

- [x] 给 `apps/phone/src/styles` 拆出基础主题文件
  - [x] `tokens.css`
  - [x] `theme.css`
  - [x] `app.css`
- [x] 把手机端现有硬编码颜色，逐步改为基础 Token
- [x] 在手机端补一个主题 store
  - [x] 支持浅色模式
  - [x] 支持深色模式
  - [x] 支持跟随系统
  - [x] 支持主色切换
- [x] 让手机端基础卡片、按钮、输入框优先吃 Token，不直接写死颜色

这一阶段的目标不是“手机端长得和云端一样”，而是“以后能低成本接云端主题能力”。

### 第二阶段：观察是否值得抽到共享包

- [ ] 当手机端和云端都稳定使用同一套主题状态模型后，再评估抽共享包
- [ ] 如果要抽，优先考虑新增 `packages/theme` 或 `packages/ui-shared`
- [ ] 不建议把主题逻辑放进 `packages/domain`

原因：

- `domain` 应该放领域逻辑
- 主题切换依赖 `document`、`localStorage`、`matchMedia`
- 这类逻辑更接近前端展示层，不属于领域层

### 第三阶段：再迁云端具体组件或页面

- [ ] 先迁真正高频的手机端业务页面
  - [ ] `auth`
  - [ ] `todos`
  - [ ] `bills`
  - [ ] `moments`
- [ ] 迁移时优先复用 `packages/api` 与 `packages/domain`
- [ ] 页面结构允许重写
- [ ] 样式优先复用 Token 和状态机制，不强求复用整段 CSS

## 目录方向建议

手机端当前已经部分落到下面这个方向：

```text
apps/phone/src/
  app/
  modules/
    auth/
    home/
    todos/
    profile/
  shared/
    components/
    composables/
    stores/
```

说明：

- [x] `modules/` 用于业务模块拆分
- [x] `shared/` 用于手机端内部共享
- [x] `packages/` 用于跨端共享

这样以后看到一个文件，基本就能判断它是：

- 手机端私有
- 手机端共享
- 跨端共享

## 明确不做的事

下面这些先不要做，避免方向跑偏：

- [ ] 不把手机端整体改造成 `CSS Modules`
- [ ] 不把云端整份 `app.css` 直接复制到手机端
- [ ] 不把博客主题系统整套搬到手机端
- [ ] 不为了复用页面而共享根布局、导航条、页面壳
